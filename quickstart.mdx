This guide covers everything you need to run Wild Guess & Match on your machine. You will clone the repository, install dependencies, configure the database connection, and start the development server.

## Prerequisites

- Node.js 22 (the CI workflow targets `node-version: '22'`)
- npm 10 or later
- A MongoDB instance (local or Atlas)
- Netlify CLI installed globally (only needed if you want to run Netlify Functions locally)

<Note>
  `netlify-cli` is not included in the project dependencies. Install it globally with `npm install -g netlify-cli` to use `netlify dev`.
</Note>

## Clone and Install

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/azru007/learn-kids.git
    cd learn-kids
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    npm install
    ```
  </Step>
</Steps>

## Configure Environment Variables

The backend functions require a MongoDB connection string. Copy the example file and edit it with your actual URI.

```bash
cp .env.example .env
```

Update `.env` with your MongoDB URI:

```bash
# MongoDB Connection String (Atlas or Local)
MONGODB_URI=mongodb://localhost:27017/wild-guess-match
```

For MongoDB Atlas, use a connection string like:

```bash
MONGODB_URI=mongodb+srv://<user>:<password>@cluster.mongodb.net/wild-guess-match?retryWrites=true&w=majority
```

## Run the Development Server

You have two options for local development:

### Option 1: Frontend Only (Vite)

Use this when you are only working on UI components and do not need the backend functions.

```bash
npm run dev
```

The Vite dev server starts on `http://localhost:5173` by default. API calls to `/api/*` will fail in this mode because there is no function router.

### Option 2: Full Stack with Netlify Functions

Use this when you are working on backend logic, database queries, or the full gameplay loop.

```bash
netlify dev
```

<Note>
  This requires `netlify-cli` to be installed globally (`npm install -g netlify-cli`).
</Note>

This command reads `netlify.toml`, builds the project, and spins up a local Netlify Functions server. The redirects defined in the config let you call `/api/player`, `/api/score`, and `/api/leaderboard/daily` as you would in production.

## Build for Production

To verify that the production build succeeds before deploying:

```bash
npm run build
```

This runs `tsc -b && vite build`, outputting a static site to the `dist/` folder. The `netlify.toml` configuration points Netlify to this directory:

```toml
[build]
  command = "npm run build"
  publish = "dist"
  functions = "netlify/functions"
```

## Preview the Production Build

```bash
npm run preview
```

This serves the built `dist/` folder locally with Vite's preview server.
